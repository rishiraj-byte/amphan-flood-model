Flood Model

Cyclone flood maps from Sentinel-1 radar (before/after pairs) · Bay of Bengal

Read scores with care. The training labels come from the published Mondal map (Zenodo 4390084), so scores against that map are optimistic. The independent score uses the NASA JPL ARIA flood proxy map.

Training record: did any recipe change beat the model in use?

Validation score = mean of the published-map and independent-map IoU on validation blocks (never test). A change counts only if it clears the old mean plus the seed-to-seed spread.

Automatic storm pipeline

  1. PC downloads the radar scenes, builds the storm stack and sends stack.tar + .sha256 over the bridge.
  2. Laptop (storm_autorun.py) waits for it and asks the PC's pc_auto.py for a fresh checksum, and for one resend if the copies differ.
  3. The laptop checks the SHA-256 and unpacks only into a new folder (no paths outside it).
  4. The laptop runs Flood Model v1 (two-model ensemble, 8-way test-time augmentation, cutoff 0.30) on the GPU, falling back to the CPU.
  5. The laptop sends the flood km² and maps back to the PC.

Both helpers stop by themselves after a set number of hours and never run code taken from a message.

Run it yourself

run_flood_model.bat STACK_FOLDER OUTPUT_FOLDER [--cpu]
./run_flood_model.sh STACK_FOLDER OUTPUT_FOLDER [--cpu]

STACK_FOLDER is a storm stack in kit v4 layout (meta.json + inputs_detect.npy + inputs_forecast.npy). Outputs: flood_class.tif, flood_probability.tif, flood_risk.tif, PNG maps, summary.json. Check the files with SHA256SUMS.txt.
